## 0. 시작하기 전에

### 디자인 시스템 (기존 C&R Space 자산 재활용)

- `tokens.css`: 색상/타이포/스페이싱
- `Button` 컴포넌트: 7 variants × 2 sizes
- `CardShell` 패턴 (단, 렌더 함수 내부 정의 금지)
- 회의실 모듈의 `Skeleton`, `Modal`, `Badge` 컴포넌트
- `UserAvatar`, `attendee` 표시 패턴
- Figma file: `ydfT0xP6nc83VxFd7GyEx4`

### 와이어프레임 표기법

| 기호 | 의미 |
|---|---|
| `┌─┐` `└─┘` | 카드/박스 영역 |
| `[ 텍스트 ]` | 버튼 |
| `( 텍스트 )` | 입력 필드 (placeholder) |
| `[● 선택]` | 체크/선택된 상태 |
| `[○ 미선택]` | 미체크 상태 |
| `🟢 🔴 ⏰ 📅` | 상태/카테고리 시각 표시 |
| `▾` | 드롭다운 |
| `…` | 더 보기/스크롤 영역 |

### 데이터 흐름 일반 규칙

- 모든 사용자 정보는 `users` JOIN으로 live 조회 (snapshot 금지)
- Live 데이터 = `bookings/checkouts.user_id → users` JOIN, 퇴사자는 `departed_users` fallback
- Zoom 미팅 생성/취소는 Edge Function 경유 (직접 Zoom API 호출 금지)
- 모든 화면에서 `auth.uid()` 기반 RLS가 자동 작동

|---|---|
| 헤더 | "Zoom 예약" + 신규 버튼 |
| 🟢 가용 풀 | `zoom_accounts.active = true AND` 현재 시간에 confirmed booking 없음 |
| 🔴 사용 중 | 현재 시간 활성 booking + 종료 예정 시각 + 예약자 + 제목 |

**인터랙션**:
- 🟢 카드 클릭 → 그 계정 미리 선택된 채로 신규 예약 모달
- 🔴 카드 클릭 → 해당 예약 상세 (취소 가능 여부 자동 판별)
- "다가오는 예약" 본인 row 클릭 → 내 예약 상세 (취소 가능)
- "다가오는 예약" 타인 row 클릭 → 읽기 전용 상세 (사용자명·제목만)
- `[ + 새 예약 ]` → 신규 예약 모달 (계정 미선택 상태)

**데이터 매핑**:
- 9개 풀 카드: `SELECT * FROM zoom_accounts WHERE active = true ORDER BY sort_order`
- 사용 중 판정: `zoom_bookings` 중 `start_time <= now() < end_time AND status='confirmed'`
- 다가오는 예약: `zoom_bookings` JOIN `zoom_accounts` JOIN `users`, RLS 통과한 모든 row


**구성요소**:

| 필드 | 비고 |
|---|---|
| 미팅 제목 | required, max 200자, `zoom_bookings.title` |
| 날짜 | 오늘 ~ 6개월 후 |
| 시작 시간 | 30분 단위, 09:00 ~ 22:00 |
| 종료 시간 | 시작 시간 +30분 ~ +4시간 (Zoom Business 한도는 30h이지만 UI 제한) |
| 계정 선택 | 1개만 선택 가능 (radio), 시간대 충돌 계정은 비활성 처리 |

**플로우 (Frontend → Edge Function)**:
```
1. [ 예약 ] 클릭
2. Frontend: zoom_bookings INSERT (status='confirmed', zoom_meeting_id=NULL)
              → RLS가 user_id=auth.uid() 검증
3. Frontend: supabase.functions.invoke('create-zoom-meeting', { booking_id })
4. 응답 대기 (loading spinner)
5-A. 200 응답: 화면 표시 (join_url, host_key 안내) → 모달 닫기 → 메인 새로고침
5-B. 에러 응답: zoom_bookings DELETE (rollback) → 토스트 에러 메시지
```

**에러 케이스**:
- 같은 시간/계정 중복 예약 시도 → DB에 충돌 인덱스가 막아줌 (`idx_zoom_bookings_account_time`) → 사용자에게 "이미 예약된 시간" 토스트
- Zoom API 실패 → rollback + 토스트

**기존 자산 재활용**: `<Modal>`, `<DateTimePicker>`, `<Button>`, `<Toast>`
